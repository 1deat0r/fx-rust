libfx · fxrs ACP over stdio

The Agent Client Protocol (ACP) wire format spoken by fxrs acp — the Rust 1:1 port of fx — as wrapped by the dependency-free libfx JavaScript SDK.

Node ≥ 20 zero deps JSON-RPC 2.0 Apache-2.0

Architecture stdio-bound today

fxrs acp is a long-lived server that reads newline-delimited JSON-RPC 2.0 requests from stdin and writes responses + streaming notifications to stdout. libfx spawns that process, writes request frames, correlates responses by id, and emits every session/update notification to your event handlers.

DirectionFrameMeaning
client → server{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":1}}negotiate protocol
server → client{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":1,"agentInfo":{...}}}capabilities + agent info
server → client{"jsonrpc":"2.0","method":"session/update","params":{"sessionId":"s…","update":{...}}}streaming event (no id)
server → client{"jsonrpc":"2.0","id":9,"error":{"code":-32602,"message":"Session not found"}}RPC error

Protocol frames, side by side a live conversation

▶ request (client writes a line)

// initialize
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":1}}

// session/new
{"jsonrpc":"2.0","id":2,"method":"session/new","params":{}}

// session/prompt (snake_case prompt_text)
{"jsonrpc":"2.0","id":3,"method":"session/prompt",
 "params":{"sessionId":"s1a..","prompt_text":"hi"}}

◀ response / notification (server writes lines)

{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":1,"agentInfo":{..."name":"fx"}}}

{"jsonrpc":"2.0","id":2,"result":{"sessionId":"s1a..","modes":{"currentModeId":"ask"}}}

// notifications stream with NO id:
{"jsonrpc":"2.0","method":"session/update","params":{
  "sessionId":"s1a..",
  "update":{"sessionUpdate":"agent_message_chunk",
    "content":{"type":"text","text":"Hello"}}}}

Streaming updates include agent_message_chunk, user_message_chunk, tool_call, tool_call_update, step_started, and available_commands_update.

libfx in 10 lines

import { FxClient } from "./libfx.mjs";
const client = new FxClient({ bin: "./target/debug/fxrs" });
await client.start();
const { protocolVersion } = await client.initialize();      // 1
const { sessionId } = await client.sessionNew({});
await client.sessionPrompt(sessionId, "say hello in one line", {
  onEvent: (ev) => {
    if (ev.sessionUpdate === "agent_message_chunk") process.stdout.write(ev.content?.text ?? "");
  },
});
await client.close();

Running in a browser WebSocket-to-stdio bridge

fxrs acp is stdio-bound today (no listen socket), so a browser page cannot talk to it directly. The plan for browser usage is a small WebSocket-to-stdio bridge that owns the child process in Node and translates line-delimited JSON to/from WebSocket messages: 

// bridge.mjs (Node side — owns fxrs acp)
import { WebSocketServer } from "ws";
import { FxClient } from "libfx";

const client = new FxClient();           // spawns fxrs acp
await client.start();
await client.initialize();

const wss = new WebSocketServer({ port: 8080 });
wss.on("connection", (ws) => {
  ws.on("message", (data) => {
    // data is a JSON-RPC request string; write it to the child:
    client.child.stdin.write(data + "\n");
  });
  client.on("update", (params) =>        // stream events back
    ws.send(JSON.stringify({ "method": "session/update", "params": params })));
});

The browser side then behaves exactly like the Node side — send request objects over ws.send, and route session/update messages to the same event handlers libfx uses. Until then, use libfx in Node or bundled with a bridge like the one above.

Note on the current fxrs build: session/new allocates a session id but the server flushes sessions to disk on the first prompt. A session/prompt against an id that was never flushed returns an RPC error — create sessions via a raw no-sessionId prompt for persistence, or wait for the server-side fix. The SDK surface stays the same either way.
